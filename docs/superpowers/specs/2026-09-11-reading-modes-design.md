# Ink 文章阅读模式设计

## 目标

在 Ink 的文章阅读页提供“分页”和“滚动”两种阅读模式，同时保留同一份 Markdown、同一 URL 和同一正文 DOM。

- 没有保存偏好时，小屏设备默认分页，大屏设备默认滚动。
- 用户主动切换后，将选择保存到本地；后续访问优先使用保存值。
- 滚动模式保持现有网页阅读体验。
- 分页模式支持左右点击和水平滑动翻页，并避免干扰正文链接、图片灯箱、文本选择等交互。
- 视觉控制保持 Ink 当前克制、低对比度的编辑式风格。

## 现有结构与边界

文章页由 `src/pages/posts/[...slug].astro` 生成。页面依次包含阅读统计、标题、元数据、封面、移动端目录、`Markdown.astro` 正文、版权卡和文章导航。

正文由 `Markdown.astro` 输出成唯一的 `.custom-md.markdown-content` 容器。现有全局脚本还会为正文图片初始化 PhotoSwipe，并由桌面目录组件读取 `.prose` 中的标题。站内导航使用 Swup，因此客户端行为不能只依赖首次页面加载。

本功能只分页 Markdown 正文。标题、元数据、封面、目录、版权卡和上一篇/下一篇维持普通文档流。这样可以避免元信息占用首屏分页高度，也不会将版权卡或文章导航截断在栏间。

## 方案选择

### 采用：CSS Columns + 轻量客户端控制器

分页模式为正文设置基于视口的固定阅读高度，通过 CSS 多栏把现有 DOM 排成等宽横向页面。客户端控制器只负责：

- 解析默认模式与保存偏好；
- 切换模式类和无障碍状态；
- 计算页数及当前页；
- 控制横向页位移；
- 处理点击、滑动、图片加载和尺寸变化；
- 在 Swup 替换页面后重新初始化，并清理旧监听器。

优点是正文不复制、不拆节点，Markdown、Pagefind、标题锚点和图片灯箱仍使用原有内容源。主要风险是复杂块级元素的跨栏表现，需要明确防断页和超高内容策略。

### 不采用：JavaScript 按高度拆分正文节点

这种方式可以精确控制每页内容，但必须处理段落拆分、嵌套列表、代码块、图片异步加载、标题锚点和窗口缩放后的重新分配，维护成本和回归风险明显更高。

### 不采用：复制正文生成独立页面

复制 DOM 会影响 Pagefind 索引、PhotoSwipe、元素 ID、链接和无障碍阅读顺序，也违背单一正文 DOM 的目标。

## 组件与文件边界

### `src/pages/posts/[...slug].astro`

在正文附近增加阅读模式控件、分页视口、左右点击热区和页码状态。Markdown 内容仍只渲染一次。控件使用原生按钮，并提供可见文字与 `aria-pressed` 状态。

### `src/utils/reading-mode.mjs`

放置可独立测试的纯逻辑：

- 合法模式常量与保存键；
- 保存值校验；
- 未保存时的小屏/大屏默认选择；
- 页数和页码边界计算；
- 判断交互目标是否应阻止热区翻页。

该模块不直接访问 DOM 或 `localStorage`，便于使用项目现有的 Node 测试方式验证。

### `src/components/ReadingMode.astro`

封装模式按钮、分页状态和客户端控制器，避免继续扩大文章路由文件。组件只依赖文章正文容器的稳定选择器，不接管 Markdown 渲染。

### `src/styles/shenhaike.css`

增加阅读模式的视觉和分页布局样式，继续沿用现有颜色变量、字体与分隔线，不引入新视觉体系。

## 模式决策与持久化

保存键使用带 Ink 命名空间的固定字符串，值仅允许 `paged` 或 `scroll`。

初始化优先级：

1. 若 `localStorage` 中存在合法值，使用该值。
2. 否则通过与现有移动端一致的 `767px` 断点判断：视口宽度不大于 767px 时分页，否则滚动。
3. 自动默认值不写入存储；只有用户点击模式按钮时才保存。

这意味着未手动选择的用户在设备或窗口环境变化后仍可获得适合当前视口的默认值；一旦手动选择，窗口尺寸变化和后续访问都不会覆盖偏好。存储不可用时仍可切换当前页面，但偏好不会跨访问保留。

## 分页布局

分页视口宽度为正文可用宽度，高度以视口为基础，并保留导航栏、模式控件和安全留白。正文在分页模式下使用：

- 固定分页高度；
- `column-width` 等于分页视口宽度；
- 明确的 `column-gap`；
- 横向承载所有栏页；
- 禁止分页容器自身出现纵向溢出。

客户端根据 `scrollWidth`、单页宽度和栏间距计算总页数，通过设置水平滚动位置显示当前页。使用即时定位，避免在减少动态效果的系统设置下出现额外动画；常规环境可使用短促平滑过渡。

下列元素尽量避免跨页断开：标题、图片及 figure、引用、列表项、表格、代码块、公式和项目已有的扩展内容块。普通长段落允许浏览器在行间分栏，否则中文长段可能产生大片空白。

对于高度超过单页可用空间的不可分割内容，不强制整体防断页：代码块、表格和公式保留自身横向滚动；图片限制最大高度并保持比例。这样可以保证内容可访问，而不是为了整块排版造成裁切。

图片完成加载、字体稳定、视口尺寸改变或正文尺寸变化时重新计算页数。重排后优先保留当前阅读进度比例，并将页码限制到新范围内。

## 交互设计

模式切换采用紧凑的双按钮分段控件，位于正文开始前，在手机和桌面端均直接可见。当前模式通过文字、底色和 `aria-pressed` 同时表达，不只依赖颜色。

分页模式中：

- 左侧约 30% 的空白点击区域上一页；
- 右侧约 30% 的空白点击区域下一页；
- 中间约 40% 不执行翻页，为后续工具栏或其他操作保留；
- 点击链接、按钮、图片、代码复制按钮、表单控件或发生文本选择时不翻页；
- 水平滑动达到距离与方向阈值后翻页，明显的垂直滑动不处理；
- 到达首页或末页时保持当前页，不循环；
- 页码显示为“当前页 / 总页数”，并通过适度的 `aria-live` 更新；
- 键盘焦点位于分页区域且不在输入控件中时，允许 Left/Right、PageUp/PageDown 翻页。

模式切换时，滚动转分页默认从第一页开始；分页转滚动时定位到当前页对应的近似正文进度，避免用户回到文章开头。切回分页时，在同一次文章访问内恢复最近页码。

## Swup 与其他功能兼容

控制器初始化必须幂等。首次加载时初始化一次；Swup `page:view` 后寻找新文章正文并初始化；内容替换前通过 `AbortController` 或等效清理函数移除旧监听器和观察器。

分页模式不修改正文节点 ID、不克隆图片、不阻止 PhotoSwipe 的图片点击，也不改变 Pagefind 标记。目录锚点被点击时，分页控制器根据目标元素所在栏切换到对应页；滚动模式仍使用浏览器原有锚点行为。

BackToTop 在滚动模式保持现状；分页模式下正文页码与顶部位置由阅读控制器管理，不依赖页面纵向滚动。

## 异常与降级

- JavaScript 不可用时只显示现有滚动正文，模式控件保持隐藏。
- `localStorage` 读取或写入抛错时忽略存储错误，不阻断阅读。
- 浏览器不支持所需多栏能力时回退滚动模式，并禁用分页按钮。
- 页数计算暂时为零或正文尚未完成布局时按一页处理，避免出现 `0 / 0`。
- 重复初始化不会重复添加监听器或观察器。

## 验证策略

### 自动化测试

先为 `reading-mode.mjs` 编写失败测试，再实现纯逻辑。覆盖：

- 合法保存值优先于设备默认；
- 非法或缺失保存值按 767px 断点选择；
- 总页数向上取整且至少为一页；
- 当前页始终限制在有效范围；
- 交互元素和文本选择阻止点击热区翻页。

运行现有阅读统计测试及新增测试，确认没有回归。

### 静态与构建检查

- `pnpm check`
- `node --test src/utils/*.test.mjs`
- `pnpm build`
- `git diff --check`

### 浏览器验证

至少验证手机宽度 375px 和桌面宽度 1440px：

- 无偏好时默认模式正确；
- 手动选择刷新后保持；
- 左右点击、滑动、键盘和边界行为正确；
- 链接、图片灯箱、复制按钮、目录锚点不误翻页；
- 图片、标题、引用、列表、代码块与版权卡没有明显裁切或错位；
- 从文章跳到另一文章后控件仍工作且无重复响应；
- 滚动模式与改动前的正文阅读方式一致；
- 深色模式和减少动态效果设置可用。

## 非目标

- 不保存每篇文章的阅读进度。
- 不增加字号、行距、主题等新阅读设置。
- 不把分页扩展到关于页或文章列表。
- 不修改 Markdown 内容模型、URL、RSS 或搜索数据源。
- 不提交部署或推送操作。
